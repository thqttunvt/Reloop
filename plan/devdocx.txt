1. HỆ THỐNG ĐANG CÓ GÌ (đọc 5 phút)
=====================================================================
ReLoop: chợ đồ điện tử cũ, hỏng. Người bán đăng tin kèm ảnh → AI gợi ý thông tin → tin lên Chợ và được
ghép với đơn vị thu mua trong bán kính chi nhánh (1–5 km). Hai đường chốt giao dịch:
  (a) báo giá của đối tác cấp 2 (giá dự kiến từ bảng giá → xác nhận → chủ tin chọn);
  (b) ra giá trong chat với bất kỳ khách nào, bên kia bấm Chấp nhận (QĐ-38).
→ giao dịch (bàn giao, ra giá lại, xác nhận giá cuối → bên kia chấp nhận, hủy sau 5 phút, thất bại, khiếu nại)
→ đánh giá 2 chiều.

Người dùng:
  • Khách          : mọi người đã đăng nhập — lướt Chợ, nhắn tin + ra giá với người bán, mua qua chat.
  • Đối tác cấp 1  : khách lẻ (cá nhân / hộ KD / DN) — đăng tin bán tối đa 3 tin đang mở (VIP 1: 5 tin,
                     10.000đ / 30 ngày); không thu mua bằng báo giá (QĐ-34, QĐ-41).
  • Đối tác cấp 2  : doanh nghiệp / hộ kinh doanh — tối đa 10 tin đang mở + chi nhánh, bảng giá, nhận tin
                     phù hợp, báo giá thu mua.
  • Admin          : duyệt đối tác, duyệt tin bị gắn cờ (chữ bất thường / nghi ảnh nhạy cảm), tranh chấp,
                     báo cáo vi phạm (xử lý theo mức), người dùng bị gắn cờ, xem chat của tin (chỉ đọc).
  • Admin tài chính: lập hóa đơn, "Đã thu", miễn / giữ phí khi khiếu nại.

Kiến trúc (serverless AWS, ap-southeast-1, account 926583575243):
  Web React (S3 + CloudFront) → API Gateway HTTP API (JWT Cognito) → 1 Lambda Node 22
  → DynamoDB single-table "reloop-core-table" (PK/SK + GSI1)
  Phụ trợ: S3 ảnh (presigned POST) · Rekognition (kiểm duyệt ảnh + đọc chữ) ·
           Bedrock Amazon Nova Pro (AI phân tích ảnh) + Guardrail · EventBridge 15 phút (job nền) ·
           CloudWatch (dashboard, 9 alarm) → SNS email cho Admin.
  Thanh toán: OFFLINE (hai bên trả tiền khi gặp). Code ví / sổ cái vẫn giữ, chưa nối.
  Doanh thu (QĐ-37, 39, 41): đăng tin miễn phí; người bán trả 10.000đ / giao dịch hoàn tất (+ 10.000đ nếu hủy rồi
  gỡ tin trong 72 giờ; + 10.000đ / 30 ngày nếu mua VIP 1). Hóa đơn gộp theo tháng (ngày 1), chuyển khoản theo mã
  RLFxxxxxx, Admin tài chính xác nhận. Nợ quá hạn > 3 ngày: không đăng tin mới; > 7 ngày: khóa mọi chức năng (QĐ-40).

2. CÀI ĐẶT & CHẠY
=====================================================================
Chạy local (không cần AWS, không có ảnh / AI):
  npm install
  cp backend/.env.example backend/.env
  npm run dev:be        → API http://localhost:3001 (dữ liệu lưu backend/.data/db.json)
  npm run dev:fe        → Web http://localhost:5173 — chọn Owner / Partner / Admin để đăng nhập giả
  npm test              → test backend (phải xanh trước khi mở PR)
  npm run typecheck     → typecheck backend + frontend

Làm việc với AWS (chỉ người có quyền, xem vai trò OPS):
  Cần: AWS CLI ≥ 2.32, Terraform ≥ 1.10, Node 22+.
  aws login --profile reloop --region ap-southeast-1
  AWS_PROFILE=reloop bash infra/deploy.sh             # build backend → terraform apply → upload web
  AWS_PROFILE=reloop bash infra/deploy.sh frontend    # chỉ web
  AWS_PROFILE=reloop AWS_REGION=ap-southeast-1 python scripts/smoke-aws.py
  AWS_PROFILE=reloop bash scripts/make-admin.sh <email> --finance   # + tự đăng ký email Admin nhận cảnh báo SNS
  ⚠ Không dùng profile mặc định của máy cho ReLoop. Không commit .env, khóa AWS.

Web dev: https://d1cjl1tvcp0r6q.cloudfront.net (bản 22/10, commit d4e2784)
Smoke test mặc định GIỮ dữ liệu test trên web (nhóm dùng để test / fix bug); --cleanup chỉ tạm ngừng tài khoản test.
Server local chạy job nền mỗi 60 giây (trên AWS: EventBridge 15 phút).

TABLE / OPTIMISTIC LOCKING            backend/src/store/table.ts, retry.ts
  interface Item { pk: string; sk: string; version?: number; gsi1pk?: string; gsi1sk?: string; [k: string]: unknown }
  type Condition = { kind: 'notExists' } | { kind: 'versionEquals'; version: number } | { kind: 'versionMissing' }
  type WriteOp   = { type: 'put'; item: Item; condition?: Condition }
                 | { type: 'delete'; pk: string; sk: string; condition?: Condition }
  interface QueryOptions { index?: 'gsi1'; skPrefix?: string; skRange?: { from?: string; to?: string };
                           limit?: number; ascending?: boolean }   // skRange gồm cả 2 đầu: BETWEEN / >= / <=
  interface Table {
    get<T extends Item>(pk: string, sk: string): Promise<T | undefined>;
    query<T extends Item>(pk: string, options?: QueryOptions): Promise<T[]>;
    transact(ops: WriteOp[]): Promise<void>;   // nguyên tử, ≤ 100 ops, lỗi điều kiện → ConditionFailedError
  }
  class ConditionFailedError extends Error { readonly failedKeys: string[] }
  const MAX_TRANSACT_OPS = 100
  putVersioned(item: Item, expectedVersion: number): WriteOp
      // expectedVersion 0 → notExists; khác 0 → versionEquals; item ghi ra version = expectedVersion + 1
  putNew(item: Item): WriteOp                       // condition notExists
  withOptimisticRetry<T>(attempt: () => Promise<T>, maxAttempts = 5): Promise<T>
      // chỉ bắt ConditionFailedError; hết lượt → 409 CONCURRENT_UPDATE; attempt() phải đọc lại mỗi lần
  Bản cài: DynamoTable(tableName, client?) — get/query bảng chính ConsistentRead; GSI eventual.
           MemoryTable(filePath?) — dev/test; dump(): Item[].
